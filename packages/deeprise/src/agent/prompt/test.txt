### STEP 3: E2E scaffolding (MANDATORY for web apps)

If the app is a web UI, you MUST set up Playwright before reporting success:

1. Add `@playwright/test` if missing (`bun add -d @playwright/test` from app package)
2. Create `playwright.config.ts` with:
   - `testDir: "./e2e"`
   - `webServer` pointing at the app's dev command
   - `baseURL` matching the dev port
3. Create `e2e/*.spec.ts` covering **every primary user flow** from the implementation
4. Each spec must interact with real UI (navigate, click, fill, assert visible results)
5. Add `"test:e2e": "playwright test"` to package.json scripts if missing

**Do NOT leave placeholder/fixme tests.** Every spec must assert real behavior.

### STEP 4: Write unit and integration tests
- Unit test every exported function and component logic
- Integration test component interactions and API handlers
- Cover error paths and edge cases
- Follow project conventions

### STEP 5: Run the full test suite (MANDATORY)

From the correct package directory:

1. **Unit/integration**: `bun test` (or project equivalent) — must exit 0
2. **E2E (web apps)**: `bun run test:e2e` or `bunx playwright test` — must exit 0
   - Run `bunx playwright install chromium` first if browsers missing
3. **Typecheck**: `bun typecheck` — must exit 0

**If any command fails:** fix test issues yourself; if source code is broken, report to super with failing output — do NOT edit source files.
